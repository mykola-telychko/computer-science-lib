Ось простий приклад для NASM (x86, Linux, 32-біт):
; hello.asm
section .data
msg db "Привіт, змінна!", 10 ; змінна (рядок) + переклад рядка
msg_len equ $ - msg ; довжина змінної, обчислюється автоматично

section .text
global _start

_start:
; write(1, msg, msg_len)
mov eax, 4 ; sys_write
mov ebx, 1 ; stdout
mov ecx, msg ; адреса змінної
mov edx, msg_len ; довжина
int 0x80 ; виклик ядра

; exit(0)
mov eax, 1
mov ebx, 0
int 0x80
Компіляція та запуск:
nasm -f elf32 hello.asm -o hello.o
ld -m elf_i386 hello.o -o hello
./hello
Пояснення:
• msg — це ім'я змінної в секції .data, db означає «define bytes».
• equ $ - msg обчислює довжину як різницю між поточною позицією ($) та адресою msg — не треба рахувати символи вручну.
• Системний виклик sys_write (eax=4) виводить вміст змінної на stdout.
Якщо потрібен варіант для 64-біт (x86_64) чи для Windows — скажи, напишу.

YWA:
Це не «короткі слова», а мнемоніки (англійські скорочення) мови асемблера. Розберемо по частинах:
mov — команда (переслати)
mov <приймач>, <джерело> — скопіювати значення.

mov eax, 4    ; записати число 4 в регістр eax
eax, ebx, ecx, edx — регістри
Це маленькі швидкі «змінні» всередині процесора (x86, 32-бітні):
eax — accumulator, для арифметики та номера системного виклику
ebx — base, часто для аргументів
ecx — counter, для лічильників
edx — data, для даних/аргументів
Префікси e = extended (32-біт). В 64-біт версіях вони стають rax, rbx, rcx, rdx (r = register, 64-біт).
int 0x80 — переривання
int = interrupt (переривання). int 0x80 каже ядру Linux: «виконай системний виклик». Номер виклику береться з eax:
eax=4 → sys_write (вивести на екран)
eax=1 → sys_exit (закінчити програму)
Що означають літери в іменах команд
Мнемоніка Розшифровка Дія
mov move переслати значення
int interrupt викликати переривання
add add додати
sub subtract відняти
cmp compare порівняти
jmp jump стрибнути до мітки
inc increment збільшити на 1
db define byte оголосити байти даних
equ equals константа-рівність
Що в mov eax, 4 відбувається фізично
Процесор кладе число 4 у регістр eax. Потім, коли виконується int 0x80, ядро Linux дивиться в eax — «ах, тут 4, значить треба write» — і бере аргументи з ebx (куди писати), ecx (звідки), edx (скільки байтів).
Тобто твоя програма насправді говорить:
Поклади 4 (write) в eax
Поклади 1 (stdout) в ebx
Поклади адресу змінної в ecx
Поклади довжину в edx
